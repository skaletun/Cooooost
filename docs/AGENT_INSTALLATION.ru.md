# Cooooost — полная инструкция для любого ИИ-агента

**Назначение:** этот документ можно передать ИИ-агенту как самостоятельное техническое задание. Агент должен установить Cooooost, правильно подключить поддерживаемые механизмы, проверить их работу и применять их при выполнении основного проекта. Руководство соответствует CLI Cooooost 1.0.0 в репозитории https://github.com/skaletun/Cooooost.

**Основное правило:** оптимизация затрат запрещена ценой потери качества, пропуска функций, тестов, требований пользователя, истории проекта, исходных файлов или проверок безопасности.

## 1. Что такое Cooooost и чего он не делает

Cooooost — локальный набор инструментов для ИИ-агентов:

- Скилл SKILL.md с правилами безопасной экономии контекста и сохранения качества.
- CLI-пакет Python 3.10+ без сторонних зависимостей во время работы.
- Реестр задачи .cooooost/state.json, содержащий цель, ограничения, критерии готовности, решения, изменённые файлы, результаты тестов, блокеры, планы и источники.
- Проверяемые SHA-256 контрольные точки реестра и восстановление.
- Архив оригинальных файлов без потерь: gzip + SHA-256 и проверка при восстановлении.
- UTF-8 индекс для выборочной загрузки релевантных фрагментов и указания их источников.
- Локальный API-шлюз OpenAI/Anthropic с безопасным по умолчанию отключённым повторным использованием ответов.
- Опциональные хуки жизненного цикла Claude Code и отдельный процесс снимков каждые 7–13 минут.

**Ограничения:** Cooooost не управляет внутренним окном контекста ChatGPT или Claude; не сбрасывает пятичасовые подписочные лимиты; не гарантирует 80% экономии. Снимок контекста на диске — это не автоматический вызов внутренней компрессии модели. «Cache 80» — название целевого режима, а не официально измеренный результат.

## 2. Прямой промпт для установки

Передайте агенту текст ниже, если он имеет доступ к терминалу и проекту:

> Установи и настрой Cooooost из https://github.com/skaletun/Cooooost для моей среды разработки и текущего проекта. Сначала определи ОС, Python 3.10+, Git, тип агента, каталог проекта и существующие настройки. Изучи README.md, SKILL.md и docs/SECURITY.md. Установи пакет с помощью pip из клона репозитория, а скилл установи через CLI в каталог моего агента. Если это Claude Code и у тебя есть разрешение менять мои настройки, подключи Claude Code hooks, сохрани резервные копии. Инициализируй Cooooost в корне текущего проекта. Внеси мои реальные цели, все критерии готовности и ограничения в реестр. Создай и проверь первую контрольную точку. Объясни, что для снимков каждые 7–13 минут необходим отдельно работающий процесс, запусти его только при наличии разрешения и долгоживущего терминала. API-шлюз Cache 80 включай только если приложение действительно использует OpenAI/Anthropic API и я разрешил его использовать; не включай повторный ответ для изменяемых запросов. Проверь cooooost doctor, status, verify и доступность установленного скилла. Никаких обходов ограничений провайдеров, удаления исходной истории или обещаний «−80%» без измерений. При продолжении работы соблюдай все первоначальные требования проекта и проверяй конечный результат.

## 3. Требования и определение среды

Агент должен иметь полномочия запускать команды и записывать необходимые файлы. Если работает только в веб-чате без командной оболочки или доступа к локальному компьютеру, он не может честно заявлять о выполненной установке; должен дать пользователю команды и объяснить ограничения.

Перед началом:

1. Определи текущий агент: Claude Code, Codex, Gemini CLI, Cursor, OpenCode либо другая среда.
2. Определи Windows PowerShell или терминал Linux/macOS.
3. Проверь Git и Python 3.10 или новее.
4. Определи два разных пути: где хранится исходный код Cooooost и корень **целевого** проекта пользователя.
5. Проверь, не установлен ли уже Cooooost: версию Python-модуля, текущие SKILL.md, Claude settings, наличие .cooooost/.
6. Работай только в рамках предоставленных разрешений. Не запускай удалённые скрипты через неподтверждённый shell-конвейер, не меняй настройки модели, которые недоступны.

Проверка окружения на Linux/macOS:

~~~bash
git --version
python3 --version
python3 -m pip --version
~~~

На Windows PowerShell:

~~~powershell
git --version
py -3 --version
py -3 -m pip --version
~~~

При отсутствии Python 3.10+ установи его официальным разрешённым способом или сообщи о препятствии. Не обходи права администратора.

## 4. Установка

### 4.1 Linux/macOS

~~~bash
git clone https://github.com/skaletun/Cooooost.git
cd Cooooost
python3 -m pip install .
python3 -m cooooost --version
python3 -m cooooost install --agent all
~~~

### 4.2 Windows PowerShell

~~~powershell
git clone https://github.com/skaletun/Cooooost.git
Set-Location Cooooost
py -3 -m pip install .
py -3 -m cooooost --version
py -3 -m cooooost install --agent all
~~~

Используй одну и ту же установленную среду Python при запуске CLI и хуков. Если политика системы запрещает глобальную установку pip, используй разрешённый virtual environment; для хуков обеспечь доступный командный интерпретатор в будущих сессиях.

### 4.3 Установка в конкретный ИИ-агент

Можно заменить all на одну из поддерживаемых целей:

| Агент | Флаг | Каталог установки скилла |
| --- | --- | --- |
| Claude Code | claude | ~/.claude/skills/cooooost/SKILL.md |
| OpenAI Codex | codex | ~/.agents/skills/cooooost/SKILL.md |
| Gemini CLI | gemini | ~/.gemini/skills/cooooost/SKILL.md |
| Cursor | cursor | ~/.cursor/skills/cooooost/SKILL.md |
| OpenCode | opencode | ~/.config/opencode/skills/cooooost/SKILL.md |

Пример установки только в Codex:

~~~bash
python -m cooooost install --agent codex
~~~

Флаг --home указывает базовый домашний каталог, а **не каталог проекта**. После установки перезапусти или обнови сессию агента и проверь обнаружение SKILL.md.

Для другого агента необходимо подтвердить, что он понимает Agent Skills и где ищет SKILL.md. При отсутствии такой поддержки можно применять CLI и инструкции вручную; автоматическая интеграция в неподдерживаемую среду **не предусмотрена**.

### 4.4 Claude Code: подключение хуков

~~~bash
python -m cooooost install --agent claude --claude-hooks
~~~

Для систем, где доступна лишь команда python3:

~~~bash
python3 -m cooooost install --agent claude --claude-hooks --python-command python3
~~~

Инсталлятор дополняет ~/.claude/settings.json, сохраняет существующие хуки и создаёт однократную резервную копию settings.cooooost-backup.json. События: SessionStart, PreCompact, PostCompact, SessionEnd. Проверь, что указанный python/python3 доступен в среде, из которой Claude Code реально запускает хуки. Факт наличия JSON-конфигурации **ещё не доказывает**, что события обрабатываются успешно. Хуки не запускают фонового демона и не инициируют внутреннюю команду /compact.

## 5. Первоначальное подключение к пользовательскому проекту

Перейди в **корень проекта пользователя**, а не в клон Cooooost. Создай реестр:

~~~bash
python -m cooooost init --project .
python -m cooooost doctor --project .
python -m cooooost status --project .
~~~

Внеси в него **настоящую** цель и критерии. Сначала выясни их из запроса пользователя и документации репозитория. Пример для рабочего проекта:

~~~bash
python -m cooooost update --project . --goal "Полностью реализовать заявленные изменения проекта" --acceptance-criteria "Функциональные и интеграционные тесты проходят" --constraints "Не удалять действующую функциональность"
python -m cooooost update --project . --acceptance-criteria "Все указанные пользовательские сценарии проверены"
python -m cooooost update --project . --sources "README.md, актуальные исходные файлы и постановка задачи пользователя"
python -m cooooost checkpoint --project .
python -m cooooost verify --project .
~~~

Каждое значение полей acceptance-criteria, constraints, decisions, files-changed, tests, blockers, next-steps, sources добавляется отдельной записью. Не подменяй реальные требования усреднёнными формулировками и не отмечай непроверенное как «готово».

Рекомендуемый цикл:

1. Сверить новое сообщение пользователя с записанной целью.
2. Выполнить ровно требуемый шаг и проверить фактический результат.
3. Записать изменённые файлы, решения и **реальные** результаты проверок.
4. Создать checkpoint перед значимым рефакторингом, обновлением окружения и естественной компрессией контекста.
5. После возобновления выполнить verify, summary и status, затем повторно открыть оригинальные файлы, где нужны детали.

Пример записи результата:

~~~bash
python -m cooooost update --project . --files-changed "src/main.ts" --decisions "Сохранён существующий API"
python -m cooooost update --project . --tests "npm test — успешно на текущей машине"
python -m cooooost update --project . --next-steps "Проверить мобильную и десктопную версии"
python -m cooooost checkpoint --project .
~~~

Факт «успешно» разрешается фиксировать только после фактического завершения соответствующей команды.

## 6. Как работает память и восстановление

Структура .cooooost/ содержит локальный реестр, контрольные точки, архив, индексы, информацию о зарегистрированных сессиях и SQLite-кэш при использовании API-шлюза. Источники могут содержать приватные данные; директорию не следует коммитить или публиковать.

Проверка:

~~~bash
python -m cooooost verify --project .
python -m cooooost summary --project .
python -m cooooost status --project .
~~~

Команда summary даёт компактный обзор реестра. Если обзор превышает лимит, она предлагает обратиться к полному .cooooost/state.json, а не молча выбрасывать критерии. Полный реестр важнее сокращённого представления; исходные документы важнее реестра.

Восстановление повреждённого реестра:

~~~bash
python -m cooooost recover --project .
~~~

**Осторожно:** recover перезаписывает именно state.json данными последней подтверждённой контрольной точки. Она не восстанавливает проектные исходники, удалённые git-коммиты или старый runtime. Перед recover сохрани копию нынешнего state.json, если она имеет диагностическую ценность. Без созданного checkpoint команда завершится ошибкой.

### Оригинальные файлы и индексы

~~~bash
python -m cooooost archive ./specification.md --project .
python -m cooooost ingest ./specification.md --project .
python -m cooooost retrieve "критерии приёмки" --project . --max-chars 12000
~~~

Команда archive возвращает JSON с подлинным sha256. Чтобы восстановить сохранённый файл, передай **этот** SHA-256 и новый путь назначения:

~~~text
python -m cooooost restore <реальный_sha256_из_archive> ./restored-specification.md --project .
~~~

Строка с угловыми скобками — схема аргумента, не команда для копирования. Применяй значение из JSON, не придумывай идентификатор. Restore отказывает в перезаписи существующих файлов без явного --overwrite. Archive поддерживает бинарные файлы; ingest — только UTF-8.

В ответе retrieve ключ complete означает исключительно достаточность бюджета для всех **найденных по словам** совпадений. Даже complete=true не гарантирует, что найдено всё по смыслу. Если информация имеет значение для реализации, обратись к оригинальному файлу. У каждого фрагмента есть SHA-256 источника и смещение; проверяй актуальность исходника после изменений.

## 7. Автоматические контрольные точки каждые 7–13 минут

Для отдельного долгоживущего терминала:

~~~bash
python -m cooooost daemon --project . --interval-min 7 --interval-max 13
~~~

Процесс блокирует терминал, пока работает. Если агент может запускать долгоживущие процессы только с одобрения пользователя — сначала получи это одобрение. Интервал случайный: от 420 до 780 секунд. На каждом цикле сохраняется снимок реестра; дополнительно архивируются те транскрипты, пути которых уже зарегистрированы Claude Code hooks. Неизвестные транскрипты демон не находит.

Однократный цикл:

~~~bash
python -m cooooost cycle --project .
python -m cooooost verify --project .
~~~

Не утверждай, что запущенный daemon «каждые 7–13 минут сжимает внутреннее окно контекста модели». Он работает **только с данными на диске** и не управляет серверной моделью.

## 8. Cache 80: безопасное использование

### 8.1 Что реально экономится

Три независимых механизма:

1. У провайдера может сработать **нативное кэширование повторяющихся префиксов**. Cooooost не управляет жизненным циклом KV-кэша провайдера и не вводит скрытых настроек.
2. У разрешённых стабильных API-запросов может применяться **повтор ранее сохранённого ответа**: новый вызов провайдера не требуется, но ответ не является свежей генерацией.
3. Выборочная загрузка проверенных фрагментов файлов помогает избежать повторной отправки больших документов, если фрагментов действительно достаточно для текущей задачи.

Ни один механизм не гарантирует −80% биллинга или увеличение пятчасового лимита подписки. Реальные денежные результаты требуют измерения на провайдере.

### 8.2 Запуск шлюза

~~~bash
python -m cooooost serve --project . --port 8765
~~~

Проверка:

~~~bash
python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8765/health').read().decode())"
~~~

Шлюз слушает 127.0.0.1:8765. Поддерживаются только POST /v1/chat/completions, /v1/responses, /v1/messages. Для OpenAI-совместимого клиента обычно подойдёт base URL http://127.0.0.1:8765/v1; для Anthropic путь зависит от клиента. Убедись, что итоговый путь запросов совпадает с поддерживаемым.

Клиент продолжает использовать собственный API-ключ. **Не вставляй ключи в команды, документацию, реестр, git или логи**. Установка скилла не перенаправляет автоматически запросы SDK.

### 8.3 Режимы ответа

| Заголовок ответа | Значение |
| --- | --- |
| X-Cooooost-Cache: BYPASS | Ответ прошёл через шлюз без локального повторного кэша |
| X-Cooooost-Cache: MISS | Запрос с включённым режимом replay не найден в кэше, выполнен upstream-вызов |
| X-Cooooost-Cache: HIT | Вернулся ранее сохранённый ответ на точно совпадающий запрос |

Кэш повторных ответов **выключен по умолчанию**. Включать для заведомо статического API-вызова разрешено только явно:

~~~http
X-Cooooost-Cache: replay
X-Cooooost-Namespace: stable-readonly-workload
~~~

Дополнительные условия: JSON-объект с model, явным temperature:0, без потоков, инструментов, вызовов внешних данных или побочных действий. Ключ учитывает upstream endpoint, содержимое JSON, хэш идентичности API-ключа, провайдера и namespace. Время действия по умолчанию — 3600 секунд, меняется флагом --ttl при запуске serve.

**Нельзя включать replay** для актуальных новостей, поиска, рыночных данных, авторизации, финансовых или медицинских решений, сторонних действий, вызовов инструментов, потоковых ответов, секретов, быстроменяющихся файлов, запросов без гарантий стабильности. Важно: даже temperature=0 не гарантирует идентичный вывод модели при повторном обращении. Разрешение на повтор допустимо лишь когда устаревшая копия ожидаемо приемлема.

### 8.4 Статистика и очистка

~~~bash
python -m cooooost stats --project .
python -m cooooost purge-cache --project .
~~~

В статистике observed_input_tokens / observed_output_tokens — зарегистрированные токены upstream-ответов, provider_cached_input_tokens — заявленные провайдером кэшированные токены входа. avoided_input_tokens_estimate / avoided_output_tokens_estimate — **оценка** предотвращённых токенов по старой записи при локальном HIT. Их нельзя суммировать в «сэкономленные оплаченные токены» или выдавать за подтверждённую сумму в валюте.

Команда purge-cache стирает локальные кэшированные ответы. Запускать её только по необходимости; это не стирает архив истории проекта.

## 9. Пример последовательности на чистом проекте

Выполнять в доступной среде Python после установки:

~~~bash
python -m cooooost init --project .
python -m cooooost update --project . --goal "Реализовать все требования текущей задачи" --constraints "Соблюдать исходное ТЗ"
python -m cooooost checkpoint --project .
python -m cooooost verify --project .
python -m cooooost summary --project .
python -m cooooost cycle --project .
python -m cooooost doctor --project .
~~~

Отдельным процессом — daemon. Ещё одним отдельным процессом — serve, **если** нужна работа через сторонний API. Сама установка скилла не требует подключения API и не оплачивает никаких запросов.

Для тестирования исходников самого Cooooost:

~~~bash
python -m unittest discover -s tests -v
~~~

Запускай в клоне Cooooost, а не в произвольном проекте. Для пользовательского проекта запускай его собственные тесты, сборку, линтеры, E2E и визуальные проверки.

## 10. Диагностика

| Проблема | Проверка и исправление |
| --- | --- |
| No module named cooooost | Сравни Python, использованный для pip install и запуска модуля; переустанови в нужный интерпретатор |
| Python ниже 3.10 | Установи поддерживаемую версию или сообщи об ограничении |
| Agent не видит скилл | Проверь, где реально расположен SKILL.md, поддерживает ли агент Skills и перезагрузил ли он сессию |
| Не срабатывают хуки | Проверь Claude Code, settings.json, команду python/python3 и факт наступления события |
| Не создаются автоматические снимки | Убедись, что отдельный процесс daemon действительно работает; один лишь install его не включает |
| Архив транскрипта пуст | Демон архивирует только ранее зарегистрированные пути; зарегистрируй через хуки или вызови archive вручную |
| В verify ошибка SHA | Не доверяй повреждённой контрольной точке; сохрани повреждённый файл для диагностики и сверь с оригиналами |
| recover не сработал | Убедись, что имеется хотя бы один verified checkpoint; recover не восстанавливает исходники |
| Cache 80 всегда BYPASS | Проверь base URL, разрешённый endpoint и критерии eligible; replay выключен по умолчанию |
| Cache 80 всегда MISS | Проверь полное совпадение JSON, провайдера, credentials и namespace, TTL и состояние базы |
| API возвращает 401 | Проверь настоящий API-ключ для выбранного провайдера; не логируй его |
| API возвращает 502 | Проверь сеть, HTTPS upstream и совместимость endpoint |
| Статистика не показывает 80% | Не подгоняй показатели. Укажи фактические hit/miss, токены, характер нагрузки и ограничения |

## 11. Безопасность и завершение задачи

Внутри .cooooost/ могут содержаться оригинальные приватные переписки, исходные документы и модельные ответы. Не коммить эту директорию, не отправляй содержимое третьим лицам без разрешения пользователя и не открывай локальный шлюз в сеть через туннели. На сервере нет полноценной пользовательской авторизации для shared deployment.

**Агент может объявить установку завершённой только если:**

1. Python-пакет установлен и его версия проверена.
2. Файл SKILL.md записан в фактически поддерживаемый каталог выбранной агентной среды.
3. Выполнены init, запись реальных критериев задачи, checkpoint, verify, doctor.
4. На тестовой сессии удалось прочесть status/summary, а после подключения Claude hooks — проверен соответствующий lifecycle event.
5. Если требовались фоновые снимки — есть работающий и доступный для наблюдения процесс daemon.
6. Если требовался API-шлюз — есть доступный /health и проверенная передача запросов в поддерживаемый provider endpoint, без раскрытия секретов.
7. Если измерялась экономия — приведены реальные данные и явно обозначено, что является оценкой.
8. Все требования основной задачи пользователя остаются в силе и проверяются отдельно.

В отчёте перечисли фактически выполненные действия, команды и результаты проверок, путь установки, путь реестра, режим Cache 80, работающие процессы, выявленные ограничения. **Не говори «всё работает» без реальных проверок**.
